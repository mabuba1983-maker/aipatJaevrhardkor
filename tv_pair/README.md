# نواة — اتصال التلفزيون والجوال (ملفين، زي ما طلبت بالضبط)

## الملفان
- **`tv_display.html`** = شاشة العرض (تفتحها كموقع بمتصفح التلفزيون). ما فيها أي نموذج ولا معالجة —
  بس تسجّل نفسها بالسيرفر، تعرض رمز، وتعرض اللي يوصلها من الجوال.
- **`MainActivity.kt` + `TvLink.kt`** = تعديل على تطبيقك (APK). المعالجة الفعلية (`Brain.answer`)
  تصير على الجوال زي ما هي دايمًا؛ الجديد بس إنها "ترسل نسخة" من كل رد للتلفزيون بعد ما يصير فعليًا.

## السيناريو بالضبط زي ما طلبته
1. تفتح `tv_display.html` بمتصفح التلفزيون → يطلع رمز كبير
2. بالجوال: زر ＋ → "📺 اتصال بالتلفزيون" → تكتب رابط السيرفر + نفس الرمز
3. يتصلوا، وتطلع لك المحادثات المحفوظة بالجوال زي العادة (ما تغير شيء بهالجزء)
4. تكتب للنموذج، يرد عليك من معالجة الجوال (Brain)، **ونفس الرد ينعرض بالتلفزيون أيضًا**
5. "أنشئ ملف" → يُكتب الملف فعليًا بالجوال (زي ما هو دايمًا)، وإذا كان HTML/JS/CSS **يترندر مباشرة
   بالتلفزيون بدون أي سيرفر إضافي** (نفس فكرة iframe اللي سويناها قبل)

## إجابات أسئلتك (أرقام حقيقية من ملف الأوزان الفعلي `nlm2.bin`، مو تخمين)
- **قدرته الاستيعابية الحالية:** فتحت `nlm2.bin` الحقيقي وقرأت رأسه مباشرة: embedding=64، hidden=384،
  مفردات=188 رمز → **تقريبًا 1,487,548 معامل فقط** (حجم الملف 5.95 ميجا يطابق هذا الرقم تمامًا). صغير
  فعلاً، لكنه **ينمو وقت التشغيل** عبر `growModel()` الموجودة أصلاً — مو رقم ثابت للأبد.
- **هل يفكر؟** نعم، `replyThink()` موجودة وتشتغل: يجرب عدة محاولات ويختار الأوضح، ويقول لك صراحة
  "🧠 وضع التفكير: جربت كذا محاولات".
- **هل بملف التلفزيون محرك متصفح، زر تشغيل تشوف هو ايش سوى؟** نعم، بنيته وصار زر **"▶ تشغيل ومعاينة"
  اختياري دايمًا** (ما يشتغل تلقائي) — يضغط، ومتصفح التلفزيون نفسه (مو سيرفر خارجي) يشغّل كود
  HTML/JS/CSS مباشرة.
- **تكلم النموذج من شاشة الجوال العادية بشكل منفصل؟** موجود، ما تغير — الاتصال بالتلفزيون اختياري دايمًا.
- **تكلم النموذج من التلفزيون مباشرة (والجوال يعالج)؟** أضفت صندوق كتابة بأسفل شاشة التلفزيون —
  بس هذا يحتاج تعديل صغير على `server.ts` (التالي بالأسفل)، لأن بروتوكوله الحالي اتجاه واحد بس
  (الجوال→التلفزيون). بدون هذا التعديل، الكتابة من التلفزيون ترسل لكن ما توصل للجوال.

## تعديل صغير مطلوب على `server.ts` (3 أسطر، ضيفه بعد كتلة `controller_input`)
```ts
// يسمح بالكتابة من التلفزيون نفسه، ترجع لكل أجهزة التحكم (الجوال) بنفس الغرفة
else if (data.type === 'tv_input') {
  if (ws.role === 'tv' && ws.roomCode) {
    const room = rooms.get(ws.roomCode);
    if (room) for (const ctrl of room.controllers) sendJson(ctrl, 'tv_command', { command: data.command });
  }
}
```

## الصدق الوحيد المتبقي
- **يحتاج سيرفر الاقتران شغّال** (`server.ts` اللي عندك من مشروع اللعبة، نفس البروتوكول بالضبط —
  `register_tv_host` / `connect_controller` / `controller_command`). بدون سيرفر وسيط، ما فيه طريقة
  يتعرفوا على بعض (الجوال والتلفزيون على شبكتين مختلفتين غالبًا، لازم وسيط).
- **إضافة Gradle وحيدة جديدة:** OkHttp (`app_build.gradle.kts` يبينها) — أندرويد ما فيها عميل
  WebSocket جاهز، وOkHttp هي المكتبة القياسية لهذا، مجانية بالكامل.
- **ما قدرت أجمّع (compile) ولا أشغّل أي من هذا هنا** — فحصته يدويًا بعناية (الأقواس متوازنة، البروتوكول
  مطابق لما شفته بـ`server.ts`)، لكن أول تجربة حقيقية لازم تصير عندك على جهاز فعلي.
- **"التفكير" المعروض بالتلفزيون حاليًا:** يظهر بعد انتهاء الرد (مع ملاحظة "🧠 وضع التفكير: جربت
  كذا محاولات" اللي أصلًا موجودة بردود Brain)، مو بث حي محاولة-بمحاولة أثناء التفكير — لأن البث
  الحي يحتاج تعديل داخل `Nlm.kt`/`Effort.kt` (حلقة التفكير الفعلية) وما بغيت أعدل كود استدلال
  النموذج الأساسي بدون قدرة أختبره، خوفًا أكسر شيء شغّال. قول لي إذا تبي هذا تحديدًا، بس بحذر أكثر.

## التركيب
1. استبدل `MainActivity.kt` الموجود، وضيف `TvLink.kt` بنفس المجلد (`android/app/src/main/java/ai/nuwaa/`)
2. استبدل `app/build.gradle.kts` بـ`app_build.gradle.kts` (أو ضيف بس كتلة `dependencies` منه)
3. ارفع `tv_display.html` لأي استضافة ويب (حتى GitHub Pages مجانية تكفي)
4. ابنِ الـAPK عبر نفس GitHub Action الموجود
