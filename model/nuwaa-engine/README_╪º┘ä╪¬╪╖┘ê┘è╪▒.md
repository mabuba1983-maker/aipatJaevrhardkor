# نواة — حزمة المحرك فقط (بدون أوزان)

هذي نسخة مجردة من مشروعك الأصلي، فيها فقط محرك GPT (`nuwaa/core`) + واجهة محلية بسيطة
(`local_chat.py`)، **بدون أي ملفات أوزان** (الأصلي كان 79 ميجا، هذي الحزمة أقل من 250 كيلو).

## وش انضاف فعليا (مو كلام، كود شغال)

1. **مرحلة سعة أكبر** `s220m_desktop` في `nuwaa/core/stages.py` — لا تتقيد بحدود الجوال،
   مخصصة لسطح المكتب/CI. **تنبيه صادق:** تكبير الحجم بدون تكبير التدريب (خطوات + بيانات)
   بنفس النسبة ما يخليه أذكى — يصير فيه أوزان أكثر بدون تدريب كافٍ، يعني ضوضاء أكثر لا فهم أكثر.

2. **تقليل الهلوسة في التوليد** (`nuwaa/core/model.py` دالة `generate`):
   - `repetition_penalty`: يمنع التكرار/اللف بدل الاعتراف إنه ما عنده جواب
   - `no_repeat_ngram`: يمنع تكرار نفس التتابع بالضبط
   - `min_confidence` + `unsure_token` (اختياري، معطل افتراضيا): لو أعلى احتمال عند النموذج
     واطئ، يقول "مو متأكد" بدل ما يخترع. هذا ما "يزيد فهمه" — بس يوقفه عن التخمين الواثق الكاذب.
   - الوضع الافتراضي (`temperature=0`) يبقى greedy زي ما كان — دقة قبل سرعة، كان موجود أصلا.

3. **تدريب مختص بالبرمجة فقط**: `.github/workflows/train-accuracy.yml` — ورشة GitHub Actions
   يدوية التشغيل، تاخذ بس ملفات data/ اللي فيها بايثون/كود، تدرب المرحلة اللي تحددها،
   وترفع الأوزان الناتجة (`model.pt`/`model.bin`) كـ Artifact — **ما تنحفظ بالمستودع**،
   فالريبو يضل بدون أوزان زي ما طلبت.

4. **واجهة محلية نظيفة** (`local_chat.py`): تكلم المحرك مباشرة (`nuwaa.core.engine.Engine`)
   بدون طبقة الذاكرة/المزاج (`conversation`/`mind`) اللي ما راجعتها ولا عدّلتها — عشان الحزمة
   اللي بين يدك تشتغل من أول تشغيل بدون أخطاء استيراد.

## الصدق اللي لازم تعرفه قبل لا تشغّل

- ما فيه أوزان هنا = النموذج **ما يفهم شيء** إلا بعد تدريب فعلي (ورشة العمل فوق، أو عندك).
- "زيادة القدرة الاستيعابية" = معمارية أكبر فقط. الفهم الفعلي يجي من التدريب، مو من حجم الكود.
- CPU على GitHub Actions أبطأ من GPU بحوالي 50 ضعف — مرحلة `s220m_desktop` تحتاج وقت حقيقي
  (آلاف الخطوات)، مو دقايق.
- ما لمست طبقة الذاكرة/الذات/التطوير الذاتي (`memory`, `mind`, `selfimprove`) ولا التكامل
  مع الأندرويد/الكاست — ركزت بس على المحرك زي ما طلبت.

## إضافات هذي الجولة (مو كلام، كود شغال ومفحوص بايثون `py_compile`)

### 1) تصحيح ذاتي حقيقي — `nuwaa/core/self_correct.py`
المحرك يكتب كود بايثون → `nuwaa/sandbox/snippet.py` يشغّله فعليًا في عملية معزولة (وقت/ذاكرة محدودة) →
لو طلع خطأ حقيقي (traceback فعلي، مو تخمين) يرجع للمحرك كنص الخطأ بالضبط ويطلب منه يصلح، لين `max_retries`.
هذا نص فقط — ما فيه رؤية ولا صور، وهذا بالضبط اللي يخليه قابل للتنفيذ الحين.

### 2) واجهة Studio — مجلد `studio/`
- `studio_server.py`: سيرفر محلي (مكتبة بايثون القياسية فقط، بدون أي تثبيت إضافي).
  شغّله: `python studio/studio_server.py --model model.pt`
- `studio.html`: الواجهة. **"إنشاء ملف" يسألك اسم الملف أول شي** (نافذة `prompt`) قبل لا ينشئه.
  **زر "معاينة":**
  - ملف `.py` → يشغّله فعليًا عبر الـsandbox ويعرض stdout/stderr الحقيقيين (نجاح أو فشل حقيقي، مو مزيّف)
  - ملف `.html/.js/.css` → يترندر **مباشرة جوا iframe بالمتصفح نفسه** (ما يحتاج Node ولا أي سيرفر —
    هذا سبب إن معاينة كود المتصفح تشتغل الحين، عكس قبل) ويلتقط أخطاء الجافاسكربت الحقيقية (`window.onerror`)
    ويعرضها بدل ما يتجاهلها.

### 3) اتصال التلفزيون — بدون أي شيء يتحمّل على التلفزيون
صُحّح المسار بعد توضيحك: **كله من الجوال، صفر على التلفزيون.** حذفت فكرة سيرفر WebSocket/صفحة
منفصلة تفتح على التلفزيون (كانت تحتاج تحميل شيء هناك). البديل الصحيح:
- `android/app/src/main/java/ai/nuwaa/CastManager.kt`: يكتشف نفس "Cast" اللي تستخدمه من إعدادات
  أندرويد (Settings > الأجهزة المتصلة > Cast) — مدمج في أندرويد، مجاني بالكامل، بدون أي مكتبة إضافية.
  يعطي اسم التلفزيون بالضبط لما تتصل.
- `android/app/src/main/java/ai/nuwaa/MainActivity.kt`: نفس ملفك الأصلي + 5 أسطر فقط لربط `CastManager`.
- `studio/studio.html`: تفتحها من متصفح الجوال فقط. تفعّل Cast من إعدادات أندرويد (مرآة الشاشة)
  والتلفزيون يعرض نفس شاشة جوالك تلقائيًا — بدون تطبيق ولا صفحة ولا أي تحميل على التلفزيون نفسه.

**صدق:** ما قدرت أجمّع أو أشغّل الكود هنا (بدون Android SDK ولا إنترنت). جرّبه عندك عبر GitHub Action
اللي يبني الـAPK، واختبره على جهاز حقيقي.

### 4) التوقف الذكي + رسائل بلا سقف عملي
`max_new` صار سقف أمان بس (20000)، مو هدف — التوقف الفعلي يصير لما النموذج نفسه يطلع رمز `EOS`،
وهذا **يعتمد على التدريب** (لازم بيانات التدريب تنتهي بـEOS صح)، مو خدعة بالكود. **صدق:** سياق
("دخول") لا نهائي فعليًا مستحيل فيزيائيًا — تكلفة الـattention تكبر بمربع الحجم، فـ4096 (الحالي)
هو "أكبر قدر عملي"، مو سقف اعتباطي. تكبيره أكثر ممكن بس يحتاج ذاكرة/حوسبة تدريب تناسبه.

### 5) رؤية بدائية (حتى لو بجودة سيئة) — `nuwaa/core/vision.py`
الصورة تُصغّر لـ16×16 رمادي (256 بكسل)، وكل بكسل أصلا رقم 0-255 = نفس توكن البايت العادي —
فما احتجنا شبكة رؤية منفصلة، بس غلّفناها بـ`IMG_START`/`IMG_END` ودخلت مع باقي النص. **صدق:**
بدون طبقة Convolution، النموذج يشوف قائمة أرقام مسطحة مو شبكة 2D — هذا سبب كونها "بجودة سيئة"
فعليًا، مو مجرد تواضع. وبدون تدريب على أزواج صورة+وصف بنفس الطريقة، هذي البايتات ما تعني له شيء،
زي أي مدخل ثاني غير مدرّب عليه. يحتاج `pip install pillow` (الاعتمادية الجديدة الوحيدة).
```python
reply = engine.reply_with_image("وش في الصورة؟", "car.jpg")
```

### 6) تطوير ذاتي تلقائي حقيقي — `nuwaa/core/auto_develop.py` + `.github/workflows/self-develop.yml`
**هذا مو "النموذج يفكر بنفسه ويعدل أوزانه" — هذا بحث معماري تلقائي حقيقي وشغّال:**
الورشة تجرب تغييرات صغيرة على إعدادات المحرك نفسه (عدد الطبقات/الحجم)، تدرب كل نسخة شوي، تقيسها
على اختبار حقيقي (`data/eval/`)، وتحتفظ تلقائيًا بالنسخة اللي فازت فعليًا — بدون أي إنسان يختار.
النتيجة تنحفظ بـ`discovered_stages.json` (كيلوبايتات، أرقام وتقييمات بس، **صفر أوزان**) وتسجل
نفسها كمرحلة اسمها `s_auto_best` جاهزة للاستخدام مباشرة. شغّلها يدويًا أو خلها تشتغل تلقائيًا كل
أحد (معدّل بالورشة). **صدق:** هذا تحسين تدريجي بطيء وبحث، مو قفزة ذكاء فجأة — وكل جيل يحتاج وقت
تدريب حقيقي (مو ثواني).

### 7) جاهزية فعلية لتدريبات مستقبلية بالجيجا (مو بس تحجيم اليوم)
فهمت قصدك: مو "خله يكبر الحين"، قصدك "لا يتكسر لما تصير عندنا بيانات وتدريبات كثيرة بالمستقبل".
صدق: **المعمارية نفسها ما فيها سقف** — نفس كتلة attention+MLP تشتغل لحجم 2 مليون أو 200 مليار،
الفرق أرقام بس. السقف الحقيقي الوحيد كان وبيضل الحوسبة (CPU مجاني vs GPU حقيقي)، مو الكود.
اللي كان فعلاً بيتكسر عند الجيجا، وصلّحته الحين:
- **`nuwaa/core/train.py` تغيّر من تحميل كل البيانات بالرام لفهرسة بالقرص** — ملف jsonl حجمه 5 جيجا
  الحين يكلّف فهرس خفيف (موقع كل سطر)، مو 5 جيجا رام فعلية. كان قبل يحمّل كل شي دفعة وحدة.
- **`--resume model.pt`**: تقدر تكمّل تدريب موجود بدل ما يبدأ من الصفر كل مرة — هذا اللي يخلي
  "تدريبات كثيرة عبر وقت طويل" تتراكم فعليًا بدل ما تضيع.
- **مراحل جاهزة لحوسبة GPU حقيقية مستقبلًا** (`s800m_gpu` ~800 مليون معامل، `s1_8b_gpu` ~1.82 مليار) —
  مسجلة بالكود، تستخدمها متى توفرت عندك حوسبة GPU حقيقية (Colab/Kaggle/إيجار)، بدون أي تعديل كود إضافي.

## التشغيل

```bash
# تدريب (محليا أو في GitHub Actions)
python -m nuwaa.core.train --stage s220m_desktop --steps 30000 --data-dir data --out model.pt

# محادثة محلية (CLI)
python local_chat.py --model model.pt --min-confidence 0.35

# واجهة Studio (افتح http://localhost:8765 بعدها، أو من التلفزيون افتح http://<IP الجهاز>:8765)
python studio/studio_server.py --model model.pt
```
